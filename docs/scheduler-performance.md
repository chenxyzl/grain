# 按需调度重构测量报告

当前实现已恢复同一 drainer 连续处理消息，仅在 Ask 时交班。独立固定调度循环原型已撤回。

环境：Go 1.27.0，linux/amd64，Intel Core i7-10700KF，GOMAXPROCS=16。原始基线为提交 `3a89111`。三种实现使用相同完成路径 benchmark，在同一机器上分别运行；时间是三次测量中位数，不是跨机器性能保证。

## 并发 Ask 注册锁修复

`examples/benchmark_test/actor_test/BenchmarkAskMore` 向 10,000 个 actor 发起并发外部 Ask。测试将 GOMAXPROCS 设置为 NumCPU × 2，再设置 parallelism=32；本机为 32 P、约 1,024 个请求协程。这与串行 `BenchmarkAskLocal` 的争用特征不同。

此前用于修复 shutdown 注册竞态的全局 Mutex 把 pending 注册串行化。锁剖析中约 99.9% 的累计锁等待归于 registerAsk 路径（不是 CPU 时间占比）。改用 RWMutex：注册持读锁直到 pending 插入完成，关闭持写锁设置关闭标记并收集等待者。pending 分片锁负责并发写入，回复/取消不反向获取注册锁。

同轮依次测修改后源码与修改前二进制，各 3 次、每次 2 秒，不开剖析且不与测试/构建并发：

| 版本 | 三次耗时 ns/op | 中位数 | 分配 |
|---|---|---:|---:|
| 修改前 Mutex | 1083、1017、1053 | 1053 ns | 296 B，6 次 |
| 修改后 RWMutex | 523.9、526.2、491.2 | 523.9 ns | 296 B，5 次 |

耗时降低约 50.2%，吞吐约为修改前 2 倍，两版均零丢信。此前诊断轮的中位数分别为 1329 ns 和 600.8 ns（临时 RWMutex 副本），环境波动影响绝对值，不混用不同轮次计算改善比例。

验证：全量测试、全量 race、vet、根模块与 examples 构建，以及注册/关闭相关 race 回归 100 轮。新增测试同时竞争回复、取消和关闭，检查有效等待者收到回复或停止错误、清理后没有 pending 残留，以及关闭后不能再注册。

复现（需要本地 etcd `127.0.0.1:2379`）：

```bash
cd examples
go test ./benchmark_test/actor_test -run '^$' -bench '^BenchmarkAskMore$' -benchmem -benchtime=2s -count=3
```

## executionGate 职责封装

在 actor 内身份版本上，将许可、owner ID、执行指针移动到 scheduler 按值持有的 `executionGate`。BaseActor 仅绑定 gate；正常处理、Ask 挂起/恢复及停止检查统一调用 `enter`/`leave`。没有新增 gate 堆对象或独立协程。编译器诊断确认 enter/leave 已内联。

使用修改前后独立测试二进制交错运行，各三轮取中位数，环境同下。首轮 16 P 完整路径：

| 场景 | 封装前 | 封装后 | 耗时变化 |
|---|---:|---:|---:|
| 单条 Tell | 697.4 ns | 775.6 ns | +11.2% |
| 64 条 Tell | 15524 ns | 16150 ns | +4.0% |
| 外部本地 Ask | 3491 ns | 3549 ns | +1.7% |
| A→B→A | 13422 ns | 14021 ns | +4.5% |

针对 Tell 再交错测三轮（`-test.cpu=1,16`）：

| 场景 | 封装前 | 封装后 | 耗时变化 |
|---|---:|---:|---:|
| 单条，1 P | 719.9 ns | 751.6 ns | +4.4% |
| 单条，16 P | 707.5 ns | 727.9 ns | +2.9% |
| 64 条，1 P | 16369 ns | 15682 ns | -4.2% |
| 64 条，16 P | 15439 ns | 15752 ns | +2.0% |

分配字节数不变：单条 120 B、64 条 5160 B、外部 Ask 376 B、回环约 1090 B。单条分配次数在不同轮次显示 2–3 次，其余分别为 66、7、22 次。复测耗时存在明显波动，尚不能确认稳定的小幅退化，也不宣称封装完全零成本；首轮较大差异不是 enter/leave 未内联导致。

封装后通过根模块全量测试、全量 race、vet，以及根模块和 examples 构建。现有回归覆盖非法协程/actor、挂起时身份撤销、重复 Ask、panic、Goexit、生命周期和空闲身份清理。

## 本次优化：actor 内执行身份

保留按需 drainer，将全局 `sync.Map` 替换为 scheduler 内的 `executionOwnerID` 和 `executingCall`。owner ID 与执行许可一起发布/撤销；Ask 先校验当前 Goid，再读取普通指针。每个 drainer 只读取一次 Goid，不再分配作用域包装对象、装箱 key 或插入/删除表项。

本轮依次运行修改前快照、当前实现、原始实现，每种三次，取中位数；测试不与构建或其他 benchmark 并发。原始实现也重新测量，避免将上一轮计时直接当成本轮基线。

| 场景 | 修改前全局表 | 当前 actor 内身份 | 耗时变化 | 本轮原始实现 |
|---|---:|---:|---:|---:|
| 单条 Tell | 833.4 ns | 666.9 ns | -20.0% | 673.7 ns |
| 64 条 Tell | 14371 ns/批 | 14631 ns/批 | +1.8% | 14516 ns/批 |
| 外部本地 Ask | 3484 ns | 3242 ns | -6.9% | 3423 ns |
| A→B→A | 13440 ns | 12523 ns | -6.8% | 13172 ns |

| 场景 | 修改前分配 | 当前分配 |
|---|---:|---:|
| 单条 Tell | 184 B，5 次 | 120 B，2 次 |
| 64 条 Tell | 5224 B，69 次 | 5160 B，66 次 |
| 外部本地 Ask | 440 B，9–10 次 | 376 B，7 次 |
| A→B→A | 1395 B，34 次 | 1089–1090 B，22 次 |

单条 Tell 已接近本轮原始实现，不能据约 1% 的差异宣称更快。批量场景增加约 1.8%，可能包含每条消息两次原子 owner 写入的成本与测量波动；本轮没有单独归因。三次中位数并非统计显著性检验。

代价是每个 actor 多保存 scheduler 引用、owner ID 和执行指针。10,000 个空闲 actor 实测额外 goroutine 为 0，堆约 839 B/actor，StackInuse 约 108 B/actor；运行时缓存会影响这些采样值。仍保留重入、非法身份拒绝、panic 恢复许可和 Goexit 清理。

当前版本通过全量测试、全量 race、身份/调度/重入/异常相关 race 测试 10 轮、vet、根模块与 examples 构建。新增并发非法 Ask 压测，以及挂起 handler 的发送回调不能借原 Goid 再次 Ask 的回归。

## 上一轮完成路径比较（全局作用域表版本）

| 场景 | 原始实现 | 已撤回的固定循环 | 按需全局表版本 | 全局表版相对原始 |
|---|---:|---:|---:|---:|
| 单条轻量 Tell 完成 | 619.2 ns | 2043 ns | 856.4 ns | +38% |
| 64 条轻量 Tell 完成 | 13698 ns/批 | 45463 ns/批 | 14287 ns/批 | +4% |
| 外部 NoReentryAsk 本地往返 | 3432 ns | 2833 ns | 3516 ns | +2% |
| A→B→A 重入回环 | 12367 ns | 17124 ns | 13597 ns | +10% |

相对固定循环原型，轻量单条/批量 Tell 耗时分别降低约 58%/69%，重入回环降低约 21%。外部 Ask 不再复用常驻 worker，所以比固定循环慢，回到接近原始实现的水平。

上一轮版本保留执行身份检查、作用域登记与 Goexit 异常清理，因此不是原始实现的逐指令复刻。单条轻消息触发一次 drainer 启停时，这些成本比较明显；批量消息将其摊薄。

| 场景 | 原始分配 | 全局表版分配 |
|---|---:|---:|
| 单条轻量 Tell | 97 B/op，约 2–3 次 | 184 B/op，5 次 |

| 外部本地 Ask | 353 B/op，7 次 | 440 B/op，约 9–10 次 |
| A→B→A | 997 B/op，22 次 | 约 1395 B/op，34 次 |

这些测试等待实际处理完成，不使用 overflow 丢弃来提高吞吐。`BenchmarkTellLocal` 只测发送，在消费者较慢时可能大量丢弃，因此不作为成功处理速度的主要依据。

## 为什么撤回固定循环

固定循环要求每条消息在调度器和执行协程之间往返，增加许可发送、完成事件和 goroutine 唤醒。按需实现直接执行下一条消息，仅 Ask 才启动后继并交班。

此前对照实验在固定循环中移除执行身份登记，单条 Tell 为 2.148μs → 2.163μs，64 条为 47.504μs → 47.306μs，基本无改善。单独测得 Goid 约 3.5ns、执行作用域查找约 18ns、drainer 登记/删除约 120ns。固定循环的主要退化来自逐消息交接；上一轮按需版本的剩余开销则包含每次 drainer 启停时的登记和分配。

## 空闲资源

上一轮全局表版本创建 10,000 个 actor，等待 Started 完成、邮箱排空、drainer 退出，再 GC 后采样：

- 额外存活 goroutine：0。
- 堆增量：约 813 B/actor。
- StackInuse 增量：约 131 B/actor。

actor 和 registry 仍保留。堆/栈统计包含 Go runtime 缓存和历史峰值，不是对象精确大小，也不保证 RSS 同时归还操作系统。已删除固定循环原型的 1 秒空闲定时器和常驻模式，不再需要空闲超时参数。

## 正确性验证

按需全局表版本通过根模块全量测试、全量 race、50 轮调度/作用域/异常/pending/重复 Ask 回归、go vet、根模块和 examples 构建。

覆盖正常与重复 Ask、自环/回环、满邮箱恢复、停车与发送/Poison 竞争、Started/handler panic 和 Goexit、异常展开前恢复许可、错误协程/actor 拒绝、pprof 共存以及 drainer 作用域回收。

未完成调用仍没有硬上限；回复超时不限制恢复执行权的等待时间。性能结论是消除了逐消息交接的大部分退化，保留安全检查有一定成本，不是宣称所有场景比原始实现更快。

## 全局表版本极轻单条 Tell 的开销拆分

在临时副本中做单 P、交错运行的对照实验，每项三次，取中位数。此处配置与上表的 16 P 不同，用于归因，不用于替换上表比率。禁用功能的副本只跑无 Ask 的 Tell benchmark，不能用于生产。

| 对照版本 | 单条完成耗时 | 分配 |
|---|---:|---:|
| 原始实现 | 657.3 ns | 97 B/op |
| 按需全局表版本 | 870.8 ns | 约 183–184 B/op |
| 全局表版本，禁用作用域表登记/删除 | 685.6 ns | 128 B/op |
| 上项再去掉每次调用的 Goexit 清理 defer | 674.3 ns | 128 B/op |

登记/删除与相关分配解释了主要差异。去掉清理 defer 的小差值接近计时波动，不据此精确拆算每个 defer 的耗时，也不建议为此删除异常保护。

alloc_space profile 确认稳态单条场景的分配构成约为：Context 80 B、启动 goroutine 的闭包 16 B、execution 24 B、executionScope 8 B、Goid 作为 interface key 的装箱 8 B、sync.Map 条目 48 B。相比原始 1 B 的 drainState，合计多约 87 B。少量初始 Goid 的装箱缓存会使平均数略低。

全局表版本每次 drainer 启停都插入/删除作用域表；单条模式无法摊薄，批量模式可以。routine.Goid 本身不是大头，状态职责拆分和变量重命名也不是原因。因此本次优先减少登记/分配，而不是重新加入逐消息协程交接或删除正确性保护。
